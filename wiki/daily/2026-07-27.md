## Moon invisible on mobile (Pixel 6) - fixed

Taylor: on a Pixel 6, only the moon's GLOW showed, no disc, on a near-full moon.

Cause: the moon body shader is `precision mediump float`, and the default
terminator style is "dither", whose Bayer helper SQUARES its coordinate:
`bayer2(a) = fract(a.x*0.5 + a.y*a.y*0.75)` fed with `gl_FragCoord.xy`.
gl_FragCoord.y counts from the BOTTOM of the viewport, so a moon high in the sky
on a tall phone arrives as y ~ 2000. mediump is fp16 on mobile GPUs (max finite
65504, so even y = 256 overflows once squared) -> +Inf -> fract() -> NaN ->
step() -> 0 -> the disc renders pure black at alpha 1, leaving only the halo (a
separate shader) visible. Desktop never showed it: ANGLE and desktop GL promote
mediump to fp32.

Fix: reduce the coordinate mod 4 before recursing (`bayer4` now does
`mod(a, 4.0)` first). The pattern has period 4 on both axes, so output is
unchanged where it already worked, and every square stays under 16 where it
didn't. Verified by A/B: same clip of the terminator band, before and after,
sha256 identical (c963a922...) - the moon body shader takes no time input, so
that crop is a valid pixel-exact comparison even though the full frame isn't
(window flicker + star twinkle ride uTime). Probe: scratch/moonShot.ts.

Audited the other `mediump` fragment shaders while in there: starField and
shootingStar use uTime in the VERTEX stage (highp by default), groundHaze only
touches small world-Y values. moon.ts was the only site squaring a screen
coordinate.

## Cards: only the header is fixed

Taylor: the details and district list have to be part of the scrolling content -
a road crossing many districts left almost no room for its own lists on a short
screen. Reverses the 2026-07-08 pinned-stats layout.

Both card shells (the columns dock and StandaloneEntityCard, which the FamilyTree
dialog uses) now render `part="pinned"` as the FIRST thing inside the scroll
viewport instead of in a fixed pane above it. The header - kind chip, title, nav
buttons - is the only fixed region. `part="pinned"` keeps its name: it still means
the summary block, it just isn't pinned in place any more.

Cards also GROW to fill the available display now (same ask, follow-up): the
height cap moved off the scroll viewport and onto the card
(`max-h-[calc(100vh-8rem)]`), with the body as a `flex-1 basis-auto min-h-0`
flex child. The 8rem budget = the dock's top-16 (4rem) + its horizontal
scrollbar row (0.75rem) + the SEED chip's row at the bottom (bottom-3 offset +
a 38px chip + a little gap). Taylor's correction: run to the bottom of the
window but keep the seed readable at a glance - with the directory closed the
dock's left edge is 12px, exactly the bottom-left HUD stack's, so a card that
reached the window bottom sat on top of the seed (measured: card bottom 1012 vs
seed top 990). Now the card bottom lands at 976 with the chip clear below it.
The taller HUD slots above the seed (side-view diagram, perf badge) are still
fair game for a full-height card. The header takes what it needs - a
wrapped title is 1.5rem taller - and the body gets the exact remainder, so no
magic constant has to guess the header height. The old `min(60vh, 100vh-16rem)`
viewport cap was leaving a third of tall screens empty.

Re-learned the hard way mid-change (it's in global memory as the ScrollArea
definite-height trap): a max-height alone does NOT make a ScrollArea scroll, and
`h-full` on the viewport resolves to auto here, which silently CLIPS the content
instead - the card looked right and lost half its rows. The fix is the
DirectoryPanel's recipe: flex column with min-h-0 at every level, viewport
h-auto.

Cards below the top of the stack now carry a "Return to Card" shadcn tooltip
(they were already jump-back targets on click, just unlabelled). It FOLLOWS the
cursor and opens with no delay (user 2026-07-27): the trigger is a whole card, so
a centre-anchored label lands over the card doing the covering, and a 300-400ms
delay reads as unresponsive on something that big. base-ui takes
`trackCursorAxis` on the tooltip ROOT (not the positioner) - IconTip gained a
`trackCursor` flag for it. The hovered card also lifts its BORDER
(`hover:border-foreground/50`, 150ms) so the hover has an edge as well as a
label - the deck dims these cards to 0.68 brightness, so it needs to go well
past border-border to read as lit. Measured: border-color 10% white -> 50% on
hover, in both views. Added `data-entity-card` to each card as a probe hook;
class-sniffing locators had been silently measuring the directory panel instead.

The DIRECTORY got the same lower bound (ControlDock's max-h 5.5rem -> 8rem): it
was covering the seed chip too (bottom 1016 vs seed top 990). Both panels now end

Verified (scratch/cardScrollProbe.ts): on a 900x620 window one viewport holds the
