## Moon invisible on mobile (Pixel 6) - fixed

Taylor: on a Pixel 6, only the moon's GLOW showed, no disc, on a near-full moon.

Cause: the moon body shader is `precision mediump float`, and the default
terminator style is "dither", whose Bayer helper SQUARES its coordinate:
`bayer2(a) = fract(a.x*0.5 + a.y*a.y*0.75)` fed with `gl_FragCoord.xy`.
gl_FragCoord.y counts from the BOTTOM of the viewport, so a moon high in the sky
on a tall phone arrives as y ~ 2000. mediump is fp16 on mobile GPUs (max finite
65504, so even y = 256 overflows once squared) -> +Inf -> fract() -> NaN ->
step() -> 0 -> the disc renders pure black at alpha 1, leaving only the halo (a
separate shader) visible. Desktop never showed it: ANGLE and desktop GL promote
mediump to fp32.

Fix: reduce the coordinate mod 4 before recursing (`bayer4` now does
`mod(a, 4.0)` first). The pattern has period 4 on both axes, so output is
unchanged where it already worked, and every square stays under 16 where it
didn't. Verified by A/B: same clip of the terminator band, before and after,
sha256 identical (c963a922...) - the moon body shader takes no time input, so
that crop is a valid pixel-exact comparison even though the full frame isn't
(window flicker + star twinkle ride uTime). Probe: scratch/moonShot.ts.

Audited the other `mediump` fragment shaders while in there: starField and
shootingStar use uTime in the VERTEX stage (highp by default), groundHaze only
touches small world-Y values. moon.ts was the only site squaring a screen
coordinate.

## Follow-up: "selected buildings with no purple arcs"

Measured rather than assumed (scratch/arcCoverageProbe.ts, default seed, mirrors
CommuteArc's building-card rules over all 14,021 buildings):

- 13,297 (94.8%) draw at least one arc; 724 (5.2%) draw none.
- Every zero-arc building has a real reason: 614 have residents but none commute
  OUT (retired / unemployed / work-from-home), 110 are workplaces whose entire
  listed staff lives in the building. Zero are dropped for a missing endpoint.
- Purely residential: 7,682 of 8,295 draw arcs; before this morning's fix that
  was 0 - which was the reported bug.

Two non-data reasons a selection can still look arc-less: the persona directory's
cold build has to land first (arcs need the directory), and arcs follow the
TOPMOST card - if the drill sits on a persona, you see that persona's arcs. The
shell-click change above closes the second one for a focused building.
